Verification · AetherOS 1.0 · amd64

Verify before you boot.

Download the ISO plus its checksum and signature files from the download page. Then work through the four steps below. A checksum proves the bytes; the signature proves the release.

The trust chain

  1. The signing key is generated offline

    An Ed25519 keypair is created on an offline or secured host. The private key is mode 0600, stored in a CI secret or hardware-backed keystore, and never enters the repository, a workflow file, or an ISO. Only the public key ships.

  2. The public key is staged inside the image

    The public PEM is written to /usr/share/aether/updates/aether-release.pub.pem at build time. Its fingerprint — SHA-256 of the SPKI DER bytes, printed as SHA256:<hex> by the key generator — is published with the release notes. Check the key in your image against that fingerprint before trusting any signature it verifies.

  3. Release metadata is signed

    release-metadata.json binds the ISO filename, byte size, SHA-256 digest, version, and timestamp. Its Ed25519 signature is embedded as base64 in the signature field and covers the canonical JSON of every other field. The status: signed marker is inside the signed bytes, so it cannot be flipped without breaking the signature.

  4. Checksums bind the ISO bytes

    SHA256SUMS carries the digest line for the ISO. Verifying it confirms that the image you downloaded is the exact image the signed metadata describes. The aether-release/1 update manifest is signed the same way and the updater refuses to apply anything whose signature is not VALID.

Private keys never ship. If a download asks you to install a private key, stop. AetherOS distributes public keys and signatures only.

Step 1 — Collect the artifacts

From the download page, save these beside the ISO in one directory:

  • aetheros-live-1.0_amd64.iso
  • SHA256SUMS
  • release-metadata.json
  • aether-release.pub.pem
  • release-manifest.json and release-manifest.json.sig when that manifest is published

Replace 1.0 with the version of the release you actually downloaded.

Step 2 — Check the SHA-256 digest

Linux

cd ~/Downloads
sha256sum -c SHA256SUMS

Expected result for a good image:

aetheros-live-1.0_amd64.iso: OK

Any FAILED line means the ISO bytes do not match the published checksum. Re-download the image before going further.

Windows (PowerShell)

Get-Content .\SHA256SUMS
Get-FileHash .\aetheros-live-1.0_amd64.iso -Algorithm SHA256 | Format-List

Compare the Hash value with the digest in SHA256SUMS. To have PowerShell make the comparison:

$want = (Get-Content .\SHA256SUMS -Raw) -split '\s+' | Select-Object -First 1
$got  = (Get-FileHash .\aetheros-live-1.0_amd64.iso -Algorithm SHA256).Hash.ToLower()
if ($got -eq $want.ToLower()) { 'ISO checksum OK' } else { throw 'checksum mismatch' }

The copy button reads that field locally. It makes no network request.

Step 3 — Verify the Ed25519 signature

Option A — repository tooling (preferred)

Run from the repository root with Python and cryptography installed. This uses the same canonical bytes and verification functions as the build.

python3 - <<'PY'
import json, pathlib
from scripts.signing.make_release_metadata import verify_metadata

meta = json.loads(pathlib.Path("release-metadata.json").read_text(encoding="utf-8"))
key  = pathlib.Path("aether-release.pub.pem")
print("METADATA OK" if verify_metadata(meta, key) else "METADATA FAILED")
PY

For a published aether-release/1 update manifest:

python3 - <<'PY'
import pathlib
from core.update.signature import verify_release

manifest = pathlib.Path("release-manifest.json").read_bytes()
payload  = verify_release(manifest, "release-manifest.json.sig", "aether-release.pub.pem")
print("MANIFEST OK", payload["schema"], payload["channel"])
PY

A bad signature, wrong schema, or expired manifest raises SignatureError and returns no payload.

Option B — OpenSSL pkeyutl

Use this when you want a standalone check without the Python package. Ed25519 needs -rawin; OpenSSL 1.1.1 or newer is required.

For the update manifest, the signature covers the canonical JSON of the whole file:

python3 - <<'PY' > canonical-manifest.bin
import json
p = json.load(open("release-manifest.json", encoding="utf-8"))
print(json.dumps(p, sort_keys=True, separators=(",", ":")), end="")
PY
openssl pkeyutl -verify -pubin -inkey aether-release.pub.pem \
  -rawin -in canonical-manifest.bin -sigfile release-manifest.json.sig

For release-metadata.json, the base64 signature lives in the signature field and the signed bytes exclude that field:

python3 - <<'PY'
import base64, json
p = json.load(open("release-metadata.json", encoding="utf-8"))
open("metadata.sig", "wb").write(base64.b64decode(p["signature"], validate=True))
unsigned = {k: v for k, v in p.items() if k != "signature"}
open("canonical-metadata.bin", "w", encoding="utf-8").write(
    json.dumps(unsigned, sort_keys=True, separators=(",", ":"))
)
PY
openssl pkeyutl -verify -pubin -inkey aether-release.pub.pem \
  -rawin -in canonical-metadata.bin -sigfile metadata.sig

OpenSSL prints Signature Verified Successfully on a match and exits non-zero on failure. On Windows the same commands work in WSL or in an OpenSSL install that provides openssl.exe.

Step 4 — Check the public key fingerprint

Confirm the key you downloaded matches the fingerprint published with the release notes:

openssl pkey -pubin -in aether-release.pub.pem -outform DER | sha256sum

The output hex must equal the SHA256:<hex> value in the release notes. The same key inside a booted image is at /usr/share/aether/updates/aether-release.pub.pem:

openssl pkey -pubin -in /usr/share/aether/updates/aether-release.pub.pem -outform DER | sha256sum

Once the fingerprint matches, the checksum passes, and the metadata signature verifies, the image is ready to flash.
