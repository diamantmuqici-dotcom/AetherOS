# Privacy

## Baseline

- Default: **no telemetry, no advertising identifiers, no behavioral tracking**.
- Crash reports / diagnostics / usage: **off by default**, opt-in only in Aether Setup → Privacy. Stored at `~/.config/aether/privacy.json`.
- No hidden cloud sync. Network privacy: NetworkManager + optional DNS (e.g., 1.1.1.1, 9.9.9.9) clearly labeled.
- No dark patterns: toggles explain exactly what turns on.

## Enforcement components

| Component | Path | Job |
|---|---|---|
| Policy | `aetheros/core/privacy/policy.py` | Pure allowlist, URL classifier, dconf renderer, finding schema |
| Scanner | `aetheros/core/privacy/audit.py` | Bounded static source audit, deterministic findings |
| CLI | `aetheros/scripts/aether-privacy.sh` | Headless `--check`, `--audit`, `--apply`, `--version` |
| Desktop defaults | `iso/config/includes.chroot/etc/dconf/db/aether.d/00-aether-privacy` | Shipped lockdown keyfile, generated by `render_dconf_keyfile()` |

The policy and scanner have byte-identical mirrors under
`iso/config/includes.chroot/usr/share/aether/core/privacy/`. The CLI is mirrored at
`usr/share/aether/scripts/aether-privacy.sh` and `usr/local/bin/aether-privacy`.
The shipped keyfile is byte-identical to `render_dconf_keyfile()` output.

## Endpoint allowlist

`ALLOWED_ENDPOINTS` is an explicit `(host, purpose)` list. A host outside it is
telemetry by definition; subdomains inherit the parent host's purpose.

| Host | Purpose |
|---|---|
| `github.com` | Signed AV definitions, release metadata, Proton-GE display link |
| `duckduckgo.com` | Browser homepage (display only) |
| `store.steampowered.com` | Gaming hub display-only link |
| `zen-browser.app` | Gaming hub display-only link |

`classify_url(url) -> (allowed, purpose, reason)` enforces:

- HTTPS only — plain HTTP is rejected (`scheme-not-https`).
- No userinfo (`user@host`) in a URL (`userinfo-forbidden`).
- Port 443 only; explicit `:443` and an omitted port are equivalent (`nonstandard-port`).
- No IP-literal hosts, IPv4 or bracketed IPv6 (`ip-literal-host`).
- Exact host or subdomain match on the allowlist; everything else is
  `host-not-allowlisted`.

Stable reasons: `empty-url`, `malformed-url`, `scheme-not-https`,
`userinfo-forbidden`, `malformed-port`, `nonstandard-port`, `empty-host`,
`ip-literal-host`, `host-not-allowlisted`, `ok`.

## Static source audit

`scan_sources(root, skip_dirs=("tests",))` walks `.py`, `.js` and `.sh` files.
It skips symlinks, ignores `tests/`, bounds the walk at 20,000 files and 8 MiB
per file, reads with replacement decoding, writes nothing, and sorts findings
by `(path, line, severity, evidence)`.

- **HIGH — harvesting APIs and third-party collectors:** `navigator.geolocation`,
  `geolocation`, `getMac`, `/sys/class/net/*/address`, `sendBeacon(`, `gtag(`,
  `googletagmanager`, `sentry`, `mixpanel`.
- **MEDIUM — generic network primitives:** `curl `, `wget `,
  `urllib.request.urlopen`, `requests.`, `XMLHttpRequest`, hard-coded `http://`
  with a non-loopback host.
- **INFO — allowlisted network call:** a MEDIUM primitive whose URL classifies
  as allowed, e.g. the signed AV definition fetch from `github.com`.
- MEDIUM findings with no URL, a denied URL, or an unclassified host stay MEDIUM.
  Localhost-only URLs are treated as offline fixtures and produce no finding.

Pattern-definition lines carry `# privacy-scan-ignore` so the detector does not
flag its own source. Each finding is a canonical dict of `severity`, `path`
(repo-relative) and `evidence` (one bounded source line).

## Dconf lockdown keys

| Schema | Key | Value | Effect |
|---|---|---|---|
| `org.gnome.system.location` | `enabled` | `false` | Location services off |
| `org.gnome.desktop.privacy` | `send-software-usage-stats` | `false` | No usage metrics |
| `org.gnome.desktop.privacy` | `report-technical-problems` | `false` | No automatic problem reporting |
| `org.gnome.desktop.privacy` | `recent-files-enabled` | `false` | No recent-file history |
| `org.gnome.desktop.privacy` | `remove-old-temp-files` | `true` | Periodic temp cleanup |
| `org.gnome.desktop.privacy` | `remove-old-trash-files` | `true` | Periodic trash cleanup |

The keyfile uses dconf slash-path sections (`[org/gnome/...]`) and GVariant
boolean values. It is a text keyfile; the CLI writes text only.

## CLI usage

```
aether-privacy --check
aether-privacy --audit [root]
aether-privacy --apply [--dest PATH] [--force]
aether-privacy --version
```

- `--check` — read-only JSON status: `privacy_keys`, `allowlist`, `dconf`
  (`target`, `present`, `matches_policy`) and `audit` (`scanned_root`, `count`,
  `by_severity`, `findings`). The audit is produced by calling `scan_sources`
  through `python3`; nothing is written.
- `--audit [root]` — JSON `{root, count, findings}` for the given root, defaulting
  to the resolved core root.
- `--apply` — writes the rendered keyfile to `$HOME/.config/dconf/00-aether-privacy`,
  or to the system path `/etc/dconf/db/aether.d/00-aether-privacy` when running as
  root, or to `--dest PATH`. Refuses to overwrite an existing file unless
  `--force` is given. Writes via a temp file plus rename; no binary content.
- `--version` — prints `aether-privacy 1.0`.

The script is argv-only: no dynamic command execution, no shell string
construction, no network calls. Python modules resolve relative to the script
(repo `core/privacy`, then `/usr/share/aether`, then `/usr/lib/aether`).

## Verification

```
python -m unittest discover -s aetheros/tests -p 'test_privacy.py' -v
```

The suite covers URL classification, keyfile parsing and shipped-file parity,
planted-fixture detection, clean-fixture silence, deterministic ordering,
CLI JSON shapes, fail-closed overwrite behavior and script source constraints.

Honest scope notes:

- The audit covers Aether's own source tree. **User-installed third-party apps
  are out of scope**; the allowlist and dconf lockdown cannot govern code that
  is not part of this build.
- **No live network verification ran here.** Endpoint classification and the
  audit were exercised offline against fixtures and local source only.
- At implementation time the tree audit produced no HIGH findings. MEDIUM
  findings were pre-existing installer package downloads, not telemetry.
